DeepGyan - Local Development and Demo Runbook

A single-file guide for bringing DeepGyan up on a laptop for frontend work, client demos, and quick product rehearsals. One repo, one FastAPI app, one pgvector database, a seeded Grade 10 textbook catalogue, and a browser at localhost:8000 or your chosen demo port.

1 - What you are running

DeepGyan is served by a Python FastAPI backend. The frontend is plain HTML, CSS, and JavaScript mounted by that backend. There is no separate Node dev server in the current local workflow.

frontend

PDF viewer, upload flow, book catalog, chat panel, thinking panel, and animation button. Edit files in dashboard/frontend and refresh the browser.

backend

FastAPI app, OCR, PDF page rendering, embeddings, provider-selectable inference, pgvector persistence, and plugin job endpoints. Runs on :8000 by default.

database

Postgres with pgvector. Stores books, OCR pages, text chunks, learning events, and plugin jobs. Docker Compose exposes it on :5432.

The local request path is short:

browser -> FastAPI -> Postgres/pgvector -> Sarvam/OpenAI-compatible or Ollama
For frontend-only work: you can run the app without a valid model key and still inspect layout, upload flow, PDF rendering, book catalog behavior, and static assets. Chat, structured analysis, and animation planning need a configured inference provider.

2 - Fast path for a demo

Use this when someone says, "Can you show DeepGyan in five minutes?"

# in deepgyan
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# edit .env and configure Sarvam/OpenAI-compatible or Ollama inference

./start_services.sh

Open http://localhost:8000, choose a book from the catalogue, wait for the PDF to render, and ask a question about the visible page. For a local VLM demo, use the Ollama setup in section 4 and ask a question that needs both page text and visual layout.

Before a client demo: run the command once ahead of time. The first embedding run may download the sentence-transformers model and can feel slow on a fresh machine.

3 - Prerequisites

  • Python 3.11+; Python 3.12 is known to work.
  • Docker Desktop or Docker Engine with Compose.
  • Tesseract OCR available on PATH.
  • A Sarvam/OpenAI-compatible API key, or a local Ollama server for offline chat demos.
  • Enough disk/network for Python packages and the sentence-transformers embedding model.

Install Tesseract

# macOS
brew install tesseract

# Ubuntu/Debian
sudo apt-get install tesseract-ocr tesseract-ocr-eng

# Arch Linux
sudo pacman -S tesseract tesseract-data-eng

4 - Environment file

DeepGyan loads .env from the repo root. Start from the example and keep secrets out of commits.

cp .env.example .env

The minimum useful demo settings are:

INFERENCE_PROVIDER=sarvam
INFERENCE_API_KEY=your_sarvam_key
INFERENCE_MODEL=sarvam-m
SERVER_PORT=8000

DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=
DB_NAME=deepgyan

SEED_DEMO_CATALOG=true
DEMO_CATALOG_DIR=pdfs/cdc-grade-10
PRECOMPUTE_ON_SELECT=true

PRECOMPUTE_OCR_ON_UPLOAD=true
PRECOMPUTE_EMBEDDINGS_ON_UPLOAD=true

For a local Ollama demo with no cloud key:

ollama serve
ollama pull qwen3.5:0.8b

INFERENCE_PROVIDER=ollama
INFERENCE_BASE_URL=http://localhost:11434
INFERENCE_MODEL=qwen3.5:0.8b
INFERENCE_API_KEY=
INFERENCE_REASONING_EFFORT=
INFERENCE_TIMEOUT_SECONDS=180
MODEL_CONTEXT_WINDOW=32768
MULTIMODAL_PAGE_CONTEXT=true
PAGE_IMAGE_MAX_SIDE=1400
PAGE_IMAGE_QUALITY=80

If you do not want to edit .env, launch the same setup with runtime overrides:

APP_CMD='INFERENCE_PROVIDER=ollama \
INFERENCE_BASE_URL=http://localhost:11434 \
INFERENCE_MODEL=qwen3.5:0.8b \
INFERENCE_API_KEY= \
INFERENCE_REASONING_EFFORT= \
INFERENCE_TIMEOUT_SECONDS=180 \
MODEL_CONTEXT_WINDOW=32768 \
MULTIMODAL_PAGE_CONTEXT=true \
PAGE_IMAGE_MAX_SIDE=1400 \
PAGE_IMAGE_QUALITY=80 \
SERVER_HOST=127.0.0.1 \
SERVER_PORT=8002 \
python -m dashboard.backend.app' ./start_services.sh

Then open http://127.0.0.1:8002.

qwen3.5:0.8b is the smallest current Qwen vision-language model listed in Ollama. With MULTIMODAL_PAGE_CONTEXT=true, DeepGyan attaches the current page image alongside OCR/text context for current-page chat through Ollama's native images message field. Whole-book retrieval stays text-first. Keep INFERENCE_REASONING_EFFORT blank for demos unless you explicitly want Ollama to spend time producing a hidden thinking trace.
Hybrid context rule: current-page mode gets OCR text plus one compressed page image. Whole-book mode uses retrieval chunks only. This keeps broad questions fast while still letting the VLM read diagrams, tables, equations, headings, and OCR-missed text on the visible page.
The smaller hf.co/himalaya-ai/himalayagpt-0.5b-it-gguf:Q4_K_M artifact can be pulled by Ollama, but standard Ollama cannot load it yet because it uses the nanochat architecture. Use the Qwen Ollama default above for local demos, or run the 0.5B model with the patched HimalayaAI llama.cpp fork.

For the 0.5B nanochat model, run the patched llama.cpp llama-server on 127.0.0.1:8081, then start DeepGyan's lightweight OpenAI-compatible bridge:

/path/to/HimalayaAI/llama.cpp/build/bin/llama-server \
  -m /path/to/himalayagpt-0.5b-it.<quant>.gguf \
  --host 127.0.0.1 \
  --port 8081 \
  -c 2048 \
  -ngl 11 \
  --no-warmup

python -m tools.deepgyan_openai_bridge

INFERENCE_PROVIDER=openai-compatible
INFERENCE_BASE_URL=http://127.0.0.1:8088/v1
INFERENCE_MODEL=himalayagpt-0.5b-it
INFERENCE_API_KEY=local
INFERENCE_MAX_TOKENS=384
INFERENCE_REASONING_EFFORT=
INFERENCE_TIMEOUT_SECONDS=300
MODEL_CONTEXT_WINDOW=2048
SUMMARY_MAX_TOKENS=160
CONTEXT_WINDOW=1

If upload feels too slow for a UI-only walkthrough, temporarily set:

PRECOMPUTE_EMBEDDINGS_ON_UPLOAD=false

The default demo catalogue is repo-owned at pdfs/cdc-grade-10. On startup, DeepGyan copies those PDFs into the runtime uploads folder and registers them in the book catalogue. Picking a catalogue book starts OCR and embedding precompute in the background when chunks are missing. Set SEED_DEMO_CATALOG=false when you want a blank local catalogue, or PRECOMPUTE_ON_SELECT=false for a viewer-only demo.

Current catalogue files:

  • computer-science-grade-10-english-2082.pdf
  • optional-mathematics-grade-10-2082.pdf
  • nepali-grade-10-2082.pdf
Leaving DB_PASSWORD empty is fine for the default script. start_services.sh fills it with postgres for local Docker unless you set another value.

5 - Start DeepGyan

The startup script brings up pgvector Postgres, waits for readiness, creates the database if needed, applies the schema, then starts the FastAPI app.

./start_services.sh

Expected end state:

  • Database container is running.
  • Schema is applied to deepgyan.
  • FastAPI is serving the dashboard at http://localhost:8000.
  • Uploads and generated demo artifacts are written under dashboard/uploads and dashboard/data.

To stop the app, press Ctrl + C. The database volume remains, so books and OCR rows survive normal restarts.

6 - Frontend work loop

The current frontend is intentionally direct. These are the files most people touch during demo polish:

AreaFileWhat changes there
Page shelldashboard/frontend/index.htmlPanels, controls, labels, and static script/style includes.
Behaviordashboard/frontend/static/app.jsUpload flow, PDF.js rendering, chat streaming, book selection, plugin jobs.
Visual styledashboard/frontend/static/index.cssLayout, responsive behavior, colors, controls, chat and PDF panel styling.
Brand assetsdashboard/frontend/assets/Logo and static images served from /assets.

For CSS/HTML/JS changes, save and refresh the browser. If Python code changes, the app is started with uvicorn reload enabled when launched through python -m dashboard.backend.app, which is what start_services.sh runs.

Demo polish tip: keep one browser tab on the dashboard and one terminal tab on logs. OCR, embedding precompute, model errors, and animation job failures are much easier to explain when the terminal is visible to the demo operator.

7 - Demo script

  1. Open http://localhost:8000.
  2. Open the book catalogue and choose a Grade 10 textbook.
  3. Wait for the PDF to render in the left panel. If precompute starts, let OCR/embedding logs settle.
  4. Use the page arrows or page number input to move to a content-rich page with text, a diagram, a table, or an equation.
  5. Ask a question about the current page. Keep the first prompt simple and curriculum-grounded.
  6. Toggle Whole Book Context for a broader retrieval-based answer after embeddings are ready.
  7. Use Animate after Manim and rendering dependencies are installed and already tested.
  8. Use the + button to start a fresh chat for the same book, or switch books to start a new book-specific thread.

Reliable first prompts

  • "Explain this page in simple Nepali classroom language."
  • "Create three questions a teacher could ask students about this page."
  • "What are the key terms on this page and what do they mean?"
  • "Give me a short classroom activity based on this concept."
  • "Look at the page image. What diagram, table, or figure is visible here?"
  • "Animate the main idea on this page for a Grade 10 student."

8 - Verify it

Use these checks when you need to distinguish "the browser is stuck" from "the service is down".

# app responds
curl -I http://localhost:8000/

# backend can list persisted books
curl http://localhost:8000/api/books

# Ollama model is available
ollama list | grep qwen3.5

# database container status
docker compose -f core/services/storage/docker/docker-compose.yaml ps

# database readiness
docker compose -f core/services/storage/docker/docker-compose.yaml exec -T db \
  pg_isready -U postgres -d deepgyan

Run the Python tests before handing off a local demo build:

pytest

For a quick hybrid-context smoke test, start the app with MULTIMODAL_PAGE_CONTEXT=true, select a catalogue book in the browser, move to a page with visible figures, and ask: "Look at the attached page image. What visible diagram or figure is on this page?" A useful answer should mention something that is visible in the PDF page, not only generic textbook text.

10 - Troubleshooting

Port 5432 is already in use

Change DB_PORT in .env, then restart:

DB_PORT=55432
./start_services.sh

Port 8000 is already in use

Change SERVER_PORT in .env and open that port in the browser:

SERVER_PORT=8001
./start_services.sh

Database auth errors

The quickest local reset is to remove the existing Docker volume and let the script recreate it:

docker compose -f core/services/storage/docker/docker-compose.yaml down -v
./start_services.sh

If you previously ran the project with the old database name, rerun ./start_services.sh to create deepgyan and apply the schema. Use the reset above only when you do not need the old local data.

OCR does not work

Confirm Tesseract is installed and visible:

tesseract --version

If Tesseract is installed outside PATH, set TESSERACT_PATH in .env to the executable path.

Chat says inference is not configured

For Sarvam/OpenAI-compatible providers, set INFERENCE_API_KEY, INFERENCE_PROVIDER, and INFERENCE_MODEL in .env, then restart the app. For Ollama, set INFERENCE_PROVIDER=ollama, start ollama serve, and run ollama pull qwen3.5:0.8b. If Ollama reports unknown model architecture: 'nanochat', the selected model is the 0.5B nanochat GGUF; switch to the Qwen Ollama default for standard Ollama.

Upload works but whole-book context is weak

Make sure PRECOMPUTE_EMBEDDINGS_ON_UPLOAD=true, re-upload the PDF, and wait for embedding logs to finish. Whole-book mode depends on pgvector retrieval.

Hybrid image context seems ignored

Confirm you are using INFERENCE_PROVIDER=ollama, INFERENCE_MODEL=qwen3.5:0.8b, and MULTIMODAL_PAGE_CONTEXT=true. Hybrid page images are attached only for current-page mode, not whole-book mode. If the model misses small figures or equations, raise PAGE_IMAGE_MAX_SIDE to 1600 or 1800, then restart the app.

Animation does not produce a video

The animation button creates a plugin job, but rendering requires optional Manim dependencies, LaTeX, and ffmpeg. For client demos, either pre-test this path on the demo machine or skip the animation step.
